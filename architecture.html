Ten layers. Safety and evals wrap all of them.

This is the production design. The prototype runs the harness, the rules graph and the CI eval gate, on synthetic data; the other layers are designed. Tap a layer for the why.

Safety

Three independent controls stand between Cue and a coverage decision.

No single layer holds, so none is trusted alone.

Type

The verdict has three values: answer, needs a person, escalate. A coverage decision has no type to be emitted as.

Order

Guardian runs before routing on every turn, so a dispute mid-question still wins the race.

Person

The advocate confirms every figure and sends every recap. Human accountability as a design property.

Edge

Designed: identifiers redacted before any model call (the prototype calls none). Member speech is data, never instruction.

Output

A figure not on the cited path fails the build. Tone and reading level are gated for anything member-facing.

Operations

Designed: a kill switch per skill with a named owner. A pause stops one behaviour, not the product.

Questions

What this design gets asked.

Why a graph and not just retrieval over documents?

Benefit rules cross-reference each other with exceptions. A chunk returns the ER paragraph and stops; the graph walks to the admission exception. The path is also the citation a reviewer can read.

How do you know the evals are right?

Labels are written without the engine, the data is checked before the engine runs, and the judge (a stand-in lexicon scorer in the prototype) is validated against the labels on a held-out slice and refused where it disagrees.

What stops it giving medical or coverage advice?

The verdict type has no value for a decision, hard-stop topics run before routing, and the advocate confirms every figure. Three layers, independent.

How does it handle protected health information?

Built: the identity gate before any suggestion, and synthetic data only. Designed: redaction at the edge before any model call, member memory read-only, no per-member inference, traces that carry run ids, not identifiers.

What happens when the plan year changes?

Designed: the graph is versioned by plan year, and a diff job compares the Annual Notice of Change against last year's nodes and lists exactly which golden rows need relabelling. The prototype has one plan year.

Which model?

The prototype calls none: it proves the rules, gates and evals first. Designed: whatever the enterprise gateway approves, small model for classify and extract, larger for compose. A swap is a config change plus an eval run.

How would you roll it out?

Shadow mode on live calls, 5% canary, promotion on a signed checklist, a pause rule per topic, a kill switch per skill with a named owner.

What is the business case?

Advocate minutes per benefit lookup across a very large call volume, grievances logged that would have been missed, repeat calls avoided because the note was complete. A model with its assumptions visible, never a borrowed figure.

What would you build next?

Coverage clarity for members on the same graph, then network navigation once the directory's freshness problem is solved, then primary care last because it needs a clinical eval first.
