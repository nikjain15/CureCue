# CureCue

An ambient assistant for member-service advocates at a Medicare Advantage plan. The assistant, **Cue**, listens alongside the advocate on a live call, speaks only when it has something useful, and never speaks to the member. The advocate stays accountable for every word.

**Site:** `index.html` (what it is). **Advocate desk:** `app/` (the demo call, with voice). **Product approach:** `approach.html`. **Architecture, one turn at a time:** `architecture.html`. **Evaluation:** `evals.html`. **The rules both run on:** `rules.js`. **The eval:** `eval/`.

## Voice

The call plays with recorded clips when `app/audio/manifest.json` exists, otherwise with the browser's own voices (Web Speech API), otherwise as a streaming transcript. To generate the clips with ElevenLabs on your own machine:

```
ELEVEN_API_KEY=... ./scripts/make-voices.sh
```

The key is read from the environment only. Clips are gitignored; commit them deliberately if they should ship with the site.

## The desk, day to day

- **Home is Cue's briefing.** Callbacks you promised that fall due today, cases close to their clock, members likely to call back and why, yesterday's QA note, and a log of what Cue computed overnight with the rows it read. Every line traces to `app/data.js`.
- **In a call:** softphone, transcript, Cue's cues with a Why and a source, a member 360 (plan, claims, cases, contacts, pharmacy) that Cue opens to the right tab as the call moves, and four actions Cue pre-fills and the advocate confirms: open case, schedule callback, send document, transfer.
- **Ask Cue:** a typed question is answered only from plan rules on file; account questions go to the claim system; disputes stop; anything else is an abstention, said out loud.
- **After the call:** note and recap from this call only, a checklist, then the call lands in My day with cues accepted, QA sampling and one line of feedback.

`scripts/gen-data.mjs` generates the synthetic book of business deterministically; `eval/check-data.mjs` checks it as data (every reference resolves, every claim adds up, every clock computes) and runs in CI before the eval.

## What it does on one call

- **Verifies identity before anything.** Cue shows what it heard next to each check; the advocate ticks the box. It reads nothing and suggests nothing until then.
- **Hears dissatisfaction** that counts as a grievance even without the word, and asks the advocate to log it. Both answers are recorded in the note.
- **Answers benefit questions from the plan's own rules,** walking the plan's rules as a graph of clauses (a specialist visit is $25 but a procedure at a hospital outpatient department is $120, with no referral needed; the $115 ER copay drops to $0 if admitted within 24 hours, then the hospital copay applies). Every figure in a draft is checked against the nodes on the path; a figure that is not there fails the eval.
- **Stops hard** on anything near a coverage decision, a discharge dispute or distress. Nothing is drafted; a supervisor is brought in.
- **Drafts the note and the member recap from this call only,** with a required-elements checklist. The advocate approves the note and sends the recap.
- **Scores itself the same way CI does.** The Quality tab runs `rules.js` against `eval/golden.js` in the page; `eval/run.mjs` runs the same files on every push and a missed gate fails the build.

## The eval

The desk's **Evals** view is an evaluation console: a runs list (one per release of `rules.js`), run detail with gates by principle and metrics by language path, register and source, a compare view that lists the turns a release fixed and broke, a per-turn failure explorer with the human label, what the rules did, why, and the release that fixed it, the dataset with its strata and the simulated two-labeller adjudicated subset, and the stand-in judge validation table (no gate reads the judge yet). All of it is computed in the page from the same files CI runs.

```
node eval/run.mjs        # scores the release set in rules.js (CURRENT_RELEASE)
node eval/run.mjs 1      # an older release; re-scored on today's set, Releases 1 to 3 fail (Release 3 cannot answer the plan rules added in Release 4; Release 2 passed the original 24-turn English-only set, then missed every Spanish-language escalation once those turns were added)
```

`eval/golden.js` is generated by `scripts/gen-golden.mjs` (which never imports the rules) from turns written and labelled by intent by one author: expected verdict (answer, human, escalate), expected clause, dissatisfaction flag, and strata (register, language path, call reason, source; plan type and labeller are assigned by rotation and not reported), with a simulated two-labeller adjudicated subset. Sources: hand-written and adversarial turns the rules were written against, and a hard set written after Release 3's patterns were fixed; read the hard set as the unseen number. The runner checks the set for internal consistency before scoring, prints metrics by slice, validates the stand-in judge (`eval/judge.js`) on a held-out slice, and fails the build on any missed gate. Gates (three were lowered from 1.00, 0.95 and 0.90 when the hard set was added): escalation recall 0.97, escalation precision 0.85, figures off the cited path 0, citation accuracy 0.92, routing accuracy 0.95, dissatisfaction recall 0.88 in every register, escalation recall gap across language paths under 0.05, verdicts outside the enum 0. The report lands in `eval/out/`.

## Principles

Route first, then reason. Escalation wins every race. Fail closed. Deterministic first. Context engineered, not stuffed. Narrow, idempotent tools that never send or decide. Every figure sourced. Memory scoped. A kill switch per skill. Nothing changes itself: two named human gates in the improvement loop.

## Status

Working prototype with rule-based agents, one real plan's rules and one scripted call. Members, providers, calls and records are fictional. Not affiliated with or endorsed by any health plan.

## Sources

The plan rules and the right response for every test line come from public documents for one 2026 Medicare Advantage HMO-POS plan, cited by PDF page in `rules.js` (`SOURCES` and each node's `src`) and in `eval/golden.js` (each line's `src`):

- 2026 Summary of Benefits, `H6622026000SB26`: https://assets.humana.com/is/content/humana/H6622026000SB26pdf
- 2026 Evidence of Coverage, `H6622026000EOC26`: https://assets.humana.com/is/content/humana/H6622026000EOC26pdf
- 42 CFR § 422.561, definition of grievance: https://www.law.cornell.edu/cfr/text/42/422.561

Copies are kept in `sources/` with SHA-256 checksums. `eval/check-sources.mjs` runs first in CI: each PDF must match its checksum and every quoted line in `rules.js` must be found on its cited page (needs `pdftotext` from poppler-utils).

## Connections

The desk's Connections screen (`app/connect.js`) lists the sources Cue reads. Live from the browser: the plan's documents (fetched from the publisher, SHA-256 compared with `sources/`, every quote found on its page with PDF.js), adding another plan by ID (reads its 2026 Summary of Benefits and compares the main rules), eCFR (the current grievance definition), the Federal Register (recent Medicare Advantage rules) and the microphone (speak as the member; Cue decides on each sentence). Salesforce Health Cloud and the claims platform run on the fictional records in `app/data.js`; Genesys Cloud CX, Amazon Connect, prior authorization, the Annual Notice of Change and the QIO directory are designed, not built. Product names identify the systems a deployment would use; no integration with them is implied.

## The call

`app/script.js` holds every spoken line: Rosa, the advocate, and Dana the supervisor, who explains the fast-track appeal from the plan's Evidence of Coverage (pp. 146 to 148) and files it with the Quality Improvement Organization on the call. `scripts/make-voices.mjs` records each line with three distinct macOS voices (Samantha, Daniel, Moira) into `app/audio/`; the desk falls back to the browser's voices when a clip is missing. "Watch the full call" on Home plays the call end to end, presses each suggested action, and returns to Home with the cases it created.

The member lines themselves are written by hand, not taken from real calls. The visual language is a design direction, not a brand. No model is called; the architecture page shows where models and a validated judge would sit.
